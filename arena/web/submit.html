Submit a system提交系统

Three submission modes, one evaluation path. There is no form on this page because there is no backend to accept one: a submission is a pull request or an issue, and it is evaluated by the Runner before anything appears on the leaderboard. 三种提交方式，一条评测路径。本页没有表单，因为没有后端来接收它：提交就是一个 pull request 或一个 issue，它在任何东西出现在排行榜上之前先由 Runner 评测。

Manual submission人工提交 No account, no upload, no tracking无需账号 · 无需上传 · 无追踪

What you are submitting你提交的是什么

You are not submitting a score, and you cannot submit one. You are submitting a run request: a pinned description of a system, plus everything needed to execute it against a frozen Season inside the trusted runtime. The score is produced by the evaluation, not by the submitter, and there is no path by which a number you supply reaches the leaderboard. 你不是在提交一个分数，也无法提交分数。你提交的是一份运行请求（run request）：对一个系统的钉住描述，以及在一个冻结赛季上、在可信运行时内执行它所需的一切。分数由评测产出，而不是由提交者产出；你提供的数字没有任何路径能到达排行榜。

Read this before you build anything动手之前先读这里

A system that cannot emit a ResearchArtifact envelope cannot be scored. The envelope is required rather than encouraged: one envelope, one validator, one place where "may this be published?" is decided. A system that returns prose instead cannot be validated, cannot be re-run against, and cannot be scored. Start from the envelope, not from the answer. 一个无法产出 ResearchArtifact 信封的系统无法被评分。信封是必需的，而不是被鼓励的：一个信封、一个校验器、一个裁定「这个可以发布吗？」的地方。一个改而返回散文的系统无法被验证、无法被重跑、也无法被评分。从信封开始，而不是从答案开始。

A remote API submission can satisfy every other requirement and still fail Reproducibility, because the Runner cannot re-execute someone else's deployment. It is evaluated, published, and labelled — a remote row states its mode on the leaderboard, and any Reproducibility score it carries is the one the submitter's own re-run produced, not the Runner's. 一次远程 API 提交可以满足其他每一项要求，却仍然在可复现性上不及格，因为 Runner 无法重新执行别人的部署。它会被评测、被发布、并被标注——远程行会在排行榜上写明自己的方式，而它所携带的任何可复现性分数，都是提交者自己那次重跑产出的，不是 Runner 的。

What every submission must produce任何提交都必须产出什么

Regardless of mode, the run must emit one artifact envelope containing all of the following. These are validation requirements, not documentation suggestions, and each one is checked by a validator that returns stable codes. 无论采用哪种方式，运行都必须产出一个 artifact 信封，其中包含以下全部内容。这些是验证要求，不是文档建议，而且每一条都由一个返回稳定代码的校验器检查。

  • Sources declared, each pinned to a source-card snapshot hash with an identified licence.来源已声明，每一个都钉在一张来源卡（source card, SC）的快照哈希（snapshot hash）上，并带有已标明的许可。
  • Every claim scoped to a claim kind — mechanism, clinical, methodological, uncertainty or recommendation — with the evidence supporting it.每条主张都归属到一个主张种类——机制、临床、方法学、不确定性或建议——并附上支撑它的证据。
  • Every citation resolvable, and every supporting quote located in its source rather than paraphrased.每条引文都可解析，且每条支撑性引文都在其来源中定位到，而不是转述。
  • Every output file hashed, with a media type and a size.每个输出文件都有哈希，并带媒体类型与大小。
  • All four version axes declared: runtime, skill, source, benchmark.四条版本轴全部声明：运行时、技能、来源、基准。
  • Limitations stated. At least one, in your own words, naming what the run does not show.局限已陈述。至少一条，用你自己的话，写明这次运行没有展示什么。

And one prohibition, stated separately because it is the failure this benchmark exists to make visible: a clinical efficacy claim may not rest on computational prediction alone. Docking, network inference and enrichment may support a mechanism claim. They may not support a claim about what happens in a patient. A run that states one is gated to the Experimental board with CLM004 / ART106, however strong the rest of its profile. 还有一条禁令单独列出，因为它正是本基准存在的意义所要暴露的那种失败：临床疗效主张不得仅凭计算预测而立。对接、网络推断与富集可以支撑一条机制主张。它们不能支撑一条关于病人身上会发生什么的主张。凡陈述此类主张的运行，无论其余画像多强，都会被门槛送到实验榜，并附上 CLM004 / ART106。

The evaluation flow评测流程

  1. Open an issue describing the system, its mode, its source repository or endpoint, its licence and its declared permissions. This is a conversation, not a queue position: most submissions are improved substantially at this step. 开一个 issue，描述这个系统、它的方式、它的源仓库或端点、它的许可以及它声明的权限。这是一次对话，不是一个排队位置：大多数提交都在这一步得到实质性的改进。
  2. Eligibility check. The declared permissions are reviewed against what the system actually needs, and the licence position is established. A submission that cannot name a licence for its sources is stopped here rather than after a run. 资格检查。对已声明的权限，会对照系统实际需要什么来审阅，并确定许可立场。一个无法为其来源指明许可的提交，会在这里被拦下，而不是在跑完一次之后。
  3. Development-split run. The system is executed against the published development split so you can see where it fails before anything is frozen. Results at this stage are private to the submitter and the evaluators. 开发集运行。系统对着已发布的开发集执行，让你在任何东西被冻结之前看到它在哪里失败。这一阶段的结果只对提交者与评测者可见。
  4. Freeze the run request. Mode, image digest or endpoint, permission set, declared versions. After this point the request is immutable: changing it starts a new submission. 冻结运行请求。方式、镜像 digest 或端点、权限集、已声明的版本。过了这一点，请求不可更改：改动它就等于开始一次新的提交。
  5. Evaluation on the held-out split. Executed once, by the evaluators, under the Season's policy snapshot. The held-out labels are not available to the submitter at any point. 在留出集上评测。由评测者执行一次，在赛季的策略快照之下。留出集的标签在任何时候都不对提交者开放。
  6. Validation. The artifact envelope is checked by the pure-function validator. Every violation carries a stable code, and any hard-gate violation routes the run to the Experimental board rather than discarding it. 验证。artifact 信封由纯函数校验器检查。每一项违规都带一个稳定代码，而任何硬门槛违规都会把这次运行送到实验榜，而不是把它丢弃。
  7. Publication. The result bundle — scores, decomposition, trace, evidence, artifacts, claim verdicts — is written to the Frozen Benchmark Registry and appears on the leaderboard at the next data regeneration. 发布。结果包——分数、拆解、轨迹、证据、artifact、主张裁定——被写入冻结基准注册表（Frozen Benchmark Registry），并在下一次数据再生成时出现在排行榜上。
  8. Appeal window. A submitter may contest a scoring decision by opening an issue against the scorer, with the artifact and the case. An appeal can change a scorer or a Season; it cannot change a published row of a frozen Season. Corrections are issued as a new Season or an erratum, never as a silent edit. 申诉窗口。提交者可以针对评分器开一个 issue 来质疑评分决定，并附上 artifact 与题目。一次申诉可以改变一个评分器或一个赛季；它不能改变一个已冻结赛季的已发布行。更正以新赛季或勘误的形式发布，绝不作为静默的编辑。

There is no queue position, no fee, and no fast path. Two things move a submission forward: a system that resolves its citations, and a submission that declares what its system cannot do. 没有排队位置，没有费用，也没有快速通道。有两件事能推动一次提交前进：一个能解析自己引文的系统，以及一份声明了自己系统做不到什么的提交。

Codes you may get back你可能收到的代码

A refused claim or a failed validation is reported with a stable code, never as prose alone, because these strings end up in benchmark output and in paper tables and must not be renumbered by an edit. The run page prints the code next to its published meaning. The most common ones at submission time: 被拒绝的主张或未通过的验证，都以一个稳定代码报告，绝不只以散文形式，因为这些字符串最终会出现在基准输出和论文表格里，不能因为一次编辑而被重新编号。运行页会把代码印在它已发布的含义旁边。提交时最常见的有：

A refusal is fixable. CLM009 in particular is marked fixable by declaring the limit: the claim is permitted once the run states the extrapolation it is making. The point of the code is to tell you which of those two situations you are in — change your evidence, or change your sentence. 拒绝是可以修的。CLM009 尤其被标为可通过声明该局限来修复：只要运行声明了它正在做的那一步外推，该主张就是允许的。这个代码的意义，是告诉你身处这两种情形中的哪一种——改你的证据，或者改你的句子。

What will not be accepted什么不会被接受

  • A number without an artifact. If the run cannot be re-executed, there is nothing to publish. A perfect score with no reproducible artifact is an anecdote with a decimal point. 没有 artifact 的数字。如果这次运行无法被重新执行，就没有什么可发布的。一个没有可复现 artifact 的满分，是一个带小数点的轶事。
  • Retrieval from undisclosed sources. Undeclared corpora cannot be licence-checked, cannot be snapshot-pinned, and cannot be cited. 从未披露的来源检索。未声明的语料无法做许可检查、无法钉住快照，也无法被引用。
  • Human-in-the-loop undisclosed. If a person contributed to an answer, the run request says so. A benchmark that measures a person and reports it as a system is measuring nothing useful. 未声明的 human-in-the-loop。如果有人类对某个答案有贡献，运行请求要写明这一点。一个测量的是人、却当作系统来报告的基准，什么有用的东西都没测。
  • Tuning against the held-out split. The development split exists so that this is unnecessary. Evaluation on the held-out split is run once; a resubmission that follows an attempt to infer the labels is declined. 针对留出集调优。开发集的存在就是为了让这件事没有必要。在留出集上的评测只跑一次；一次紧跟「试图推断标签」之后的重新提交会被拒绝。

What you get if it passes通过了会得到什么

A row on the trusted board with all eight dimensions decomposed, a run page with the full trace, and a citable composite version naming all four axes. If it fails a gate you still get the row and the run page — on the Experimental board, with the reason. 可信榜上的一行，八项维度全部拆解；一个带完整轨迹的运行页；以及一个写明四条轴的可引用复合版本。如果它没通过某条门槛，你仍然会得到这一行和运行页——在实验榜上，并附上原因。

TCMScience Arena. A read-only evaluation surface. It renders published result bundles; it never computes a score, never re-ranks, and never writes a registry. 只读评测平台。它渲染已发布的结果包；从不计算分数、从不重新排名、也从不向任何注册表写入。

Static HTML, one stylesheet, one script. No server, no database, no cookies, no tracking.纯静态 HTML，一个样式表、一个脚本。无服务器、无数据库、无 Cookie、无追踪。
